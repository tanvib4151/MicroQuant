# Positive staining area, algorithm positive-area/1.1.0

For the chosen raw plane and half-open rectangle `[x0,x1) × [y0,y1)`, take `values = plane[y0:y1,x0:x1]`, and `mask = (values >= lower) & (values <= upper)`. Positive pixels are `np.count_nonzero(mask)`; total pixels are `values.size`. Positive area (%) is `100.0 * positive_pixels / total_pixels`. Bounds are integer original-image coordinates and must be inside the image with positive width and height; invalid rectangles are rejected, never silently clipped by the API. The interactive drawing surface clips pointer positions. Threshold bounds must be ordered integers within the original unsigned datatype range. Zero and all-positive masks return exactly 0% and 100%.

RGB uint8 channels are extracted directly in red/green/blue order. Grayscale uses its single intensity plane, not a color mixture. `auto` resolves to grayscale or green for initial inspection only; it does not infer marker identity. Marker is a user label. 66–255 is an 8-bit demonstration default, not a scientifically validated threshold. The UI changes the upper bound to 65535 after identifying uint16 input.

Accepted inputs are single-frame unsigned 8-bit or 16-bit grayscale PNG/TIFF and 8-bit RGB PNG/JPEG/TIFF (JPEG grayscale is also supported). TIFF must explicitly be MINISBLACK grayscale or contiguous RGB with three samples; stacks, planar RGB, TIFF alpha, palette, signed, floating and ambiguous formats are rejected. Non-default orientation metadata is rejected rather than implicitly rotating pixels. No EXIF transpose is applied. Big-endian uint16 is converted only to native byte order without value changes. JPEG decoded pixels already reflect lossy compression and may be unsuitable for quantitative comparisons. Unsupported compression may require exporting an uncompressed supported TIFF.

There is no histogram equalization, normalization, smoothing, background subtraction, contrast stretching, gamma correction or enhancement. Scientific processing always uses the decoded array at original bit depth. Original file bytes are hashed SHA-256, and not changed. Browser previews are separate arrays: uint8 identity; uint16 `floor(value / 257)` across the full representable range. No auto contrast. Browser resizing uses nearest-neighbor pixelated rendering to avoid visually blurring pixel boundaries. Original preview means an unchanged spatial/color rendering, with this explicit display-only mapping when necessary. Previews and PNG export preserve original dimensions. Positive ROI pixels are blended red with user opacity, then a one-pixel cyan ROI outline is drawn inside the rectangle. At boundary pixels the cyan line takes visual precedence. Neither blending nor the boundary affects measurements. For tiny images the border may obscure the overlay; numeric counts remain authoritative.

Saturation fraction is the count of ROI pixels equal to 255 or 65535 divided by ROI size. A descriptive warning reports any saturation with no universal biological cutoff. Zero-positive and fully positive selections receive contextual warnings. API/JSON/CSV retain floating precision; UI percentage rounds to three decimals. CSV includes filename, marker, channel, dimensions, dtype, format, thresholds, ROI bounds, counts, percent, saturation, algorithm version, preview mapping and source hash. JSON includes the same settings plus QC and display opacity. CSV prefixes spreadsheet formula-like marker/filename text with an apostrophe for safety; JSON retains the original descriptive text.

Threshold-positive area is a fraction of pixels, not cell count, percent positive cells, protein concentration, expression quantity, activation or disease severity. Background fluorescence, autofluorescence, acquisition exposure/gain, saturation, preparation, non-specific staining, compression and uneven illumination affect interpretation. A zero result does not establish absence of staining. Threshold choice remains a scientific decision informed by controls. Comparisons require consistent acquisition, controls, anatomical sampling, channel definitions, ROI and analysis procedures. Batch comparisons and inference are outside V1. Users must manually exclude scale bars, borders, annotations and non-tissue. Published figure measurements are exploratory because provenance, adjustments and region selection may be unknown. No scientific validation or Fiji equivalence is claimed.

Fully opaque RGBA PNGs are accepted automatically: only the all-255 alpha plane is discarded, preserving every RGB value. PNGs with any transparent or partially transparent pixel are rejected with an explanation; no background compositing occurs. The source hash still identifies the original RGBA upload. TIFF alpha and palette images remain unsupported.

## Optional automatic Otsu threshold, version 1.1.0

`threshold_method` is `manual` (the backward-compatible default) or `otsu`. In Otsu mode the backend validates the ROI and computes its histogram from the raw selected plane: exactly 256 bins for uint8 or 65536 for uint16. No downsampling, normalization or histogram range remapping occurs. For each integer split t, the dark class is intensity ≤ t and the bright class is intensity > t. Choose the split maximizing between-class variance `w0*w1*(mean0-mean1)^2`, ignoring empty classes. Weights may be counts; the normalization constant does not affect the optimum. Histogram accumulation and scoring use float64 after integer bin counting. Equal computed scores choose the earliest (lowest) split via NumPy argmax.

The selected inclusive threshold bounds are `[t+1, dtype_max]`. This distinction prevents off-by-one errors when applying Otsu's strictly brighter class through the existing inclusive measurement formula. User-supplied numeric bounds do not determine the measurement in Otsu mode; the selected method recomputes them. The actual chosen bounds and method are returned and exported. The algorithm version is now positive-area/1.1.0; manual counting semantics remain unchanged. An ROI with fewer than two distinct intensities has no meaningful split and is rejected with instructions to switch to Manual. No arbitrary cutoff is substituted.

Auto selection is driven only by pixels inside the ROI; changing ROI or channel recomputes the threshold. Preview scaling and overlay opacity do not enter the histogram. Otsu treats brighter intensities as foreground without knowing whether they are staining, background, artifacts or autofluorescence. It does not guarantee a biologically correct threshold, Fiji-equivalent automatic threshold behavior or valid cross-sample comparison. Use controls, inspect overlays and define a consistent protocol before group comparisons. It is not appropriate for all histograms, illumination patterns or foreground proportions.

## Export provenance and datatype-ceiling terminology

The displayed metric is threshold-positive ROI area; it does not infer tissue. The displayed ceiling metric is pixels at datatype maximum. API/CSV `datatype_max_fraction` counts values equal to the decoded unsigned dtype maximum and `saturation_fraction` is a deprecated compatibility alias. Neither detects clipping below that ceiling (for example 4095 in a uint16 container), and neither a ceiling-valued pixel nor a zero fraction establishes instrument saturation status. This definition is always visible and exported. Acquisition notes do not modify this ceiling or any calculation.

Exports with `export_schema_version=1.1.0` include validated `image_source` (unspecified/laboratory/synthetic/published), optional `sample_id`, `acquisition_notes`, `control_reference`, measurement/ceiling definitions, `warnings` and `interpretation_notes`. CSV list fields are JSON-encoded cells; JSON retains native lists. Formula-like user text is apostrophe-prefixed in CSV only; the original text remains in JSON. A source hash proves identity with supplied bytes, not acquisition authenticity or biological validity. The numerical algorithm remains positive-area/1.1.0 because counting and Otsu semantics were unchanged. Published provenance produces an exported exploratory-use caution; missing source remains explicitly unspecified. These annotations are not assay validation.
